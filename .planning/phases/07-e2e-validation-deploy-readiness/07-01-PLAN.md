|----------|-------------|

| live variant -> real SaaS provider | Crossed ONLY under `-m live` with a provider token present; the write is draft/sandbox + reversible. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-07-02 | Information Disclosure | provider token / approval token leaking into test output | accept (low) | Tokens read from metadata are not logged; default lane uses no creds; SEC-01 redaction (public_task_dict) already proven in test_approval_security.py. |
| T-07-03 | Repudiation | green-on-a-lie if assertions read a different repo than HTTP mutated | mitigate | Mandatory `app_module._service = svc` rebind (SP-1) bound into acceptance criteria. |
| T-07-SC | Tampering | npm/pip installs | n/a | No new packages installed by this plan (tests reuse existing deps). |

No HIGH-severity threats: this plan adds test code only and exercises existing, already-hardened seams. The single elevated concern (real live write) is contained to a reversible draft/sandbox path gated behind the `live` marker + provider token.
