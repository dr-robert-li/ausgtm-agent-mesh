# Phase 06 Plan 02: Held-out Evaluation Harness Summary

Replaced the boolean `evaluate_proposal` scoring stub with a real held-out evaluation harness: a creds-free Langfuse `run_experiment` over a versioned, deterministic frozen-context held-out pool, feeding a pure-Python aggregate-plus-item-level no-regression gate against a committed golden baseline.

## What Was Built

**Task 1 — `eval_harness.py` runner + frozen-item builder + held-out pool (commit c1e9d5a)**
- `build_frozen_items(snapshots)` — deterministic `LocalExperimentItem`-shaped dicts; identical input -> identical dict (SI-01c).
- `held_out_pool()` / `held_out_item_ids()` — the distinct, importable held-out **pool identity** (SI-01a). `held_out_item_ids()` returns `{"holdout-001", "holdout-002", "holdout-003"}`.
- `run_candidate(items, task_fn, *, evaluators)` — lazy-imports `langfuse`, builds a key-less `Langfuse()` (disabled, no upload) and still runs the experiment locally over the frozen items. Verified creds-free against langfuse 4.7.1.
- `replay_task` (deterministic offline replay returning `expected_output`, no model call) + `exact_match` evaluator (`Evaluation(name="exact_match", value=float(output==expected_output))`) + `scores_by_item` extractor keyed by stable `item_id`.

**Task 2 — no-regression gate + golden baseline + body swap (commit 00dc0bd)**
- `passes_no_regression(candidate, baseline, *, item_threshold)` — two-stage (D-03): candidate-mean < baseline-mean -> `(False, [{"reason":"aggregate_below_baseline"}])`; any item with `baseline - candidate > threshold` -> `(False, [regressions])`; else `(True, [])`. A dropped item scores 0.0 (worst-case regression). Pure stdlib, kept out of `run_experiment`.
- `load_baseline(version=...)` — creds-free loader for `tests/fixtures/holdout_baseline.json`.
- `tests/fixtures/holdout_baseline.json` — committed golden baseline, **generated by running `replay_task` over `held_out_pool()`** so candidate == baseline by construction.
- `self_improvement.evaluate_proposal` — scoring engine swapped: with no `deterministic_checks` it runs the held-out harness + gate (`evaluator="holdout-harness"`); with explicit checks it runs them as before (`evaluator="deterministic-checks"`). The `can_run=False`/`pending` branch, the `EvaluationResult` shape, `repo.upsert_evaluation`, and the `_set_status` mapping are untouched.

## Held-out Pool Identity (for 06-03's zero-overlap test)

- **Accessor:** `agent_mesh.services.eval_harness.held_out_item_ids() -> set[str]` (and `held_out_pool()` for the full items).
- **item_id scheme:** stable string ids `holdout-001`, `holdout-002`, `holdout-003`, carried in each frozen item's `metadata.item_id`.
- **Version pin:** `eval_harness.HELD_OUT_VERSION = "2026-06-07"` keys both the pool and the golden baseline.
- 06-03's proposer must mine only durable traces and assert `not (train_ids & held_out_item_ids())` (T-06-03b, SI-01a).
