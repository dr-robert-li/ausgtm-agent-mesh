## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local profile config → model backend | A profile's per-route `api_base` chooses where model traffic egresses. A loopback URL keeps it on-box; a cloud URL leaks egress out of an "offline" lane. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Information Disclosure | config/model_gateway.{vllm,ollama}.yaml | mitigate | A local profile silently retaining a cloud `api_base` (Vertex/Anthropic/Cloudflare-wrapper URL) or a cloud-key env ref would leak egress out of the offline lane. Mitigation (D-06 + Phase-11 invariant, enforced at authoring time): drop the cloud `high-complexity-vertex` 4th route; every route's `api_base` is loopback only (`http://localhost:8000/v1` for vLLM, `http://localhost:11434` for Ollama); strip all cloud env-refs (`CF_AIG_WRAPPER_URL`, `vertex_*`, `ANTHROPIC_API_KEY`, `x-gateway-shared-secret`). Acceptance criteria assert these via `grep -c ... == 0`. The inert `general_settings.master_key: os.environ/MODEL_GATEWAY_MASTER_KEY` is a prod-proxy field never consumed by `build_router` (D-09) — not a cloud provider key — and is intentionally retained. |
| T-08-SC | Tampering | npm/pip/cargo installs | accept | This phase installs NO Python packages (config/Makefile/docs/tests only). vLLM/Ollama are operator-installed local runtimes invoked by best-effort `make` targets, never project deps — no install surface to audit (RESEARCH Package Legitimacy Audit). |
</threat_model>
