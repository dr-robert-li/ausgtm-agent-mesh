Ship the Bitscale direct adapter (TOOL-03) as an own-file module — the FIFTH real direct
adapter (live-curl validated `api.bitscale.ai/api/v1`, `X-API-Key` auth). Three ops:

STUBBED even in the live lane — it must NEVER auto-burn the client's credits on their real
`australiagtm.com` workspace. Its write path is proven through the default-lane deterministic
stub + the upstream approval gate, never a live call. The live test file is reads-only and
must contain no run_grid call.

This plan touches ONLY `tools/adapters/bitscale.py` + its two tests + its doc. It does NOT edit
the manifest, schemas, pyproject, the registry, gateway.py, or the README / credential-docs
guard (05-01 / 05-07) — so it runs parallel with the other four wave-2 adapter plans.

so this adapter registers EXACTLY ONE dispatcher under `bitscale` routing by `spec.name` via
`_BITSCALE_OPS = {"bitscale_list_grids": _list_grids, "bitscale_get_workspace": _get_workspace,
"bitscale_run_grid": _run_grid}`. The keys MUST match the manifest op names 05-01 froze.

Purpose: prove the direct_api style on a credit-metered provider where the write path must be
proven WITHOUT spend.
