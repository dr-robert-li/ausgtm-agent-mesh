<objective>
Ship the Webflow direct adapter (TOOL-03) as an own-file module registered with the 04-03
registry — `webflow_list_cms_items` (read, unconditional live call) and `webflow_create_cms_item`
(publishing write, approval-gated upstream, always `isDraft:true`). The adapter calls the
Webflow Data API v2 over core httpx (no SDK, no new dependency) and degrades to the gateway
stub when `WEBFLOW_API_TOKEN` is absent (D-11). Plus the per-provider credential/scope doc.

This plan touches ONLY `tools/adapters/webflow.py` + its two tests + its doc. It does NOT edit
the manifest, schemas, pyproject, the registry, gateway.py, or `docs/credentials/README.md` /
`tests/test_credential_docs.py` (all owned by 05-01 / 05-07) — so it runs parallel with the
other four wave-2 adapter plans.

Critical (op-name contract from 05-01): both Webflow tools share `provider: webflow`, and
execute() dispatches direct tools by `spec.provider`, so this adapter registers EXACTLY ONE
dispatcher under `webflow` that routes by `spec.name` via `_WEBFLOW_OPS = {"webflow_list_cms_items":
_list, "webflow_create_cms_item": _create}`. The keys MUST match the manifest op names 05-01 froze.

Purpose: prove the direct_api style on a publishing provider (read + approval-gated draft write).
Output: registered Webflow adapter (one dispatcher), default-lane unit test (fake httpx +
collision guard), opt-in live test (skips without the token), credential doc.
</objective>
