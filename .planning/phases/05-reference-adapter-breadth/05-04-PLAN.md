<objective>
Ship the Cal.com direct adapter (TOOL-03) — `calcom_list_bookings` (read, unconditional live
call) + `calcom_create_booking` (write, approval-gated upstream). The adapter calls Cal.com API
v2 over core httpx (no SDK, no new dependency) and degrades to the gateway stub when
`CALCOM_API_KEY` is absent (D-11). Cal.com is the canonical multi-op direct provider with a
natural read+write pair — the `_CALCOM_OPS` single-dispatcher map is the exact collision-guard
shape RESEARCH calls out.

Critical extra: every Cal.com v2 bookings call REQUIRES the dated header
`cal-api-version: 2026-05-01` (a missing/wrong version 400s) in addition to `Authorization:
Bearer <key>`. Both ops must send it.

This plan touches ONLY `tools/adapters/calcom.py` + its two tests + its doc. It does NOT edit
the manifest, schemas, pyproject, the registry, gateway.py, or the README / credential-docs
guard (05-01 / 05-07) — so it runs parallel with the other four wave-2 adapter plans.

Op-name contract (05-01): both tools share `provider: calcom`; register EXACTLY ONE dispatcher
under `calcom` routing by `spec.name` via `_CALCOM_OPS = {"calcom_list_bookings": _list,
"calcom_create_booking": _create}`. Keys MUST match the manifest op names 05-01 froze.

Purpose: prove the direct_api style on a scheduling provider with a mandatory dated API-version
header and a real read+write pair.
Output: registered Cal.com adapter (one dispatcher), default-lane unit test (fake httpx +
collision guard + header assertion), opt-in live test, credential doc.
</objective>
