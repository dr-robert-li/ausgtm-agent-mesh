<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ingress → worker (Pub/Sub) | Task ids cross the message transport; a poison message must not wedge the worker |
| setup helper → emulator/GCP | Topic/subscription provisioning must be safe to re-run |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering / DoS | _run_pubsub poison message | mitigate | existing callback `message.nack()`s on exception so Pub/Sub retries and DLQs via the subscription's dead-letter config (validated, not rebuilt) |
| T-02-02 | Repudiation | topic/subscription provisioning | mitigate | idempotent setup helper swallows `AlreadyExists`; re-runs converge to the same transport state without masking other errors |
| T-02-03 | Information Disclosure | task id payload | accept | only the opaque `task_id` is published (no PII in the message body); durable task content stays in Postgres |
</threat_model>
