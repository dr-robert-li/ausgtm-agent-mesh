<objective>
Build the JSON-Schema validation boundary (TOOL-02) as a standalone, importable module
that the execution engine (04-03) calls input-pre-call and output-post-call. This plan
owns ONLY `tools/validation.py` so it runs parallel with the engine plan (04-03 owns
gateway.py). The validator encodes the three locked decisions exactly:

- **D-04 source-by-style:** validate direct tools against OUR manifest-declared schemas;
  aggregate tools against a runtime provider schema the caller supplies (this plan exposes
  the seam; the aggregator plan fills it). Fail-closed applies to DIRECT tools ONLY — a
  direct tool with no schema is BLOCKED; an aggregate tool with no runtime schema is NEVER
  blocked.
- **D-05 permissive-by-design:** the validator faithfully applies whatever the schema
  declares (additionalProperties, enums, bounds) — gate width is the schema author's
  choice, not the validator's.
- **D-06 asymmetric failure:** input violation raises `InputSchemaViolation` (caller makes
  NO SaaS call, records a failed tool_call); output violation raises/returns
  `OutputSchemaViolation` material (caller flags/quarantines — the call already ran).

Purpose: A creds-free, deterministic boundary that the success-criterion-#2 reject test
exercises in the default lane.
Output: `tools/validation.py` + `tests/test_schema_boundary.py` covering all four D-04/D-06
cases against tools that DO declare schemas.
</objective>
