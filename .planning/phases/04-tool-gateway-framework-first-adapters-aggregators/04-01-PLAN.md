Lay the contract, persistence, manifest, and dependency foundation that every other
Phase-4 plan builds on. Three concerns, deliberately grouped so Wave-2/3 plans never
contend on shared files (the advisor's catch #2):

1. **ToolCall additive fields (audit item D)** — `integration_style`, `schema_validation`,
   `is_read` on the `ToolCall` contract, the migration that adds the columns, the
   repository.py 4-place ripple (column list, INSERT/ON CONFLICT, `_row_to_tool_call`),
   and the regenerated `ToolCall.schema.json` + parity test. This is a hard dependency for
   BOTH the engine (writes `schema_validation`) and the read seam (sets `is_read=True`).
2. **All Google Workspace manifest entries + every GWS schema file (D-08 x D-04)** — add
   Calendar/Docs/Slides tool entries and author `input_schema_ref`/`output_schema_ref` for
   every direct GWS tool so a later adapter plan never has to touch the manifest. A declared
   tool with no adapter is harmless (uncallable); a declared tool with no schema is BLOCKED
   under D-04 fail-closed, so the schemas MUST land with the manifest entries.
3. **pyproject extras (D-12 prep)** — `tools` + `aggregators` optional-dependency groups
   and `jsonschema` promoted to a core dependency, so the schema boundary is never an
   optional import while provider SDKs stay opt-in (keeps the default lane creds-free).

Purpose: Make Wave-2 (validator, engine) and Wave-3 (adapters, aggregators) genuinely
parallel by giving them stable contract/manifest/dependency surfaces that already exist.
Output: An additive migration, a wider ToolCall, every GWS schema, the manifest entries,
and the pyproject extras — all with the default suite still green and creds-free.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01-01 | Tampering | manifest write-class entry with approval_required:false | mitigate | ToolSpec.validate (gateway.py:31-37) raises at load if a write-class GWS entry omits approval_required:true; Task 2 acceptance criterion asserts it |
| T-04-01-02 | Tampering | new ToolCall columns altering existing rows | mitigate | additive-only migration (ADD COLUMN IF NOT EXISTS, defaults); extra="forbid" + contract-parity test forbid a rewrite of the P1 contract |
| T-04-01-SC | Tampering | npm/pip/cargo installs | mitigate | this plan declares extras but installs NOTHING; every install is gated by a blocking-human checkpoint in the adapter plans (T-04-01-SC carried forward); nango PyPI is forbidden (DO-NOT-INSTALL) |
| T-04-01-03 | Information disclosure | schema files leaking real resource ids | accept | schemas use REPLACE_WITH placeholders / generic field shapes; no live ids committed |

No high-severity threats: this plan adds no execution path, no credential handling, and installs nothing.
</threat_model>
