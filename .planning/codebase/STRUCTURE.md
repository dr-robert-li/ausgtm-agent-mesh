## Directory Purposes

**`src/agent_mesh/`:**
- Purpose: Reusable core platform (POC scaffold importable without cloud dependencies).
- Contains: Contract models, task orchestration, ingress API, worker runner, approval gating, tool gateway, self-improvement loop, observability seam.
- Key files: `settings.py` (configuration), `contracts/models.py` (all data shapes), `services/task_service.py` (orchestration hub), `api/app.py` (FastAPI ingress), `worker/runner.py` (execution).

**`migrations/`:**
- Purpose: Cloud SQL schema (Postgres + pgvector).
- Contains: DDL for tasks, sessions, memory/evidence chunks, approvals, budgets, gateway events, LangGraph checkpoints, self-improvement records.
- Key files: `0001_init.sql` (baseline), `0002_self_improvement.sql` (proposals/evaluations/promotions).
- Governance: Idempotent (IF NOT EXISTS); tenant-partitioned (every table has `tenant_id`); append-only audit trails.

**`schemas/`:**
- Purpose: Exported JSON Schema from Pydantic contracts + tool I/O schemas.
- Contains: Contract schema (TaskRecord, ApprovalRecord, etc.) + tool-specific input/output schemas (HubSpot, Google Drive).
- Generated by: `make schemas` → `src/agent_mesh/contracts/export_schemas.py`.
- Use: Validation on ingress; documentation for tool integrators; API schema discovery.

**`manifests/`:**
- Purpose: Deployment-specific configuration (tenant, stack, model routes, tool packs).
- Contains: `deployment.manifest.yaml` (GCP region, Cloudflare account, budget, ingress config), `tool_pack_manifest.yaml` (per-client SaaS tools).
- Governance: Copy per client/environment; fill values before deployment scripts.
- Key fields: `stack.agent_framework` (REQUIRED: langchain+langgraph+deepagents), `model_routes` (routing profiles), `tool_packs.manifest_path` (loaded at runtime).

**`config/`:**
- Purpose: Service configuration (not secrets).
- Contains: `model_gateway.config.yaml` (LiteLLM routing tiers, preferred/fallback models per complexity).
- Governance: Deployed via gcloud; versioned in git (no credentials here).

**`cloudflare/`:**
- Purpose: Cloudflare Worker for AI Gateway wrapper (model-traffic governance plane).
- Contains: `wrangler.toml` (environment, bindings), `src/index.ts` (Worker script).
- Governance: Deployed via `scripts/cf_deploy_ai_gateway_worker.sh`; integrates with GCP service accounts and Langfuse.

**`docker/`:**
- Purpose: Container images for cloud deployment.
- Contains: Dockerfiles for API service, worker, GUI console, code executor.
- Governance: Built by `scripts/gcp_deploy_core.sh`; pushed to Artifact Registry; reference versioned images in Cloud Run.

**`scripts/`:**
- Purpose: Idempotent deployment automation.
- Contains: `gcp_bootstrap.sh` (GCP foundation), `gcp_deploy_core.sh` (Cloud Run, jobs, Pub/Sub), `cf_deploy_ai_gateway_worker.sh` (Cloudflare).
- Governance: Safe to re-run; detect existing resources before creation; environment variables for tenant, region, project ID.

**`tests/`:**
- Purpose: Unit + integration tests (no cloud, no credentials).
- Contains: Contract validation, state machine, approval gating, self-improvement loop, tool pack loading, Slack verification, end-to-end smoke test.
- Run: `make test` (pytest); `make smoke` (end-to-end in-process).

**`docs/`:**
- Purpose: Architecture & operational decision documents.
- Contains: Ecosystem rationale, governance alignment, self-improvement design, production hardening checklist.

**`.planning/codebase/`:**
- Purpose: GSD codebase analysis (generated by `/gsd:map-codebase`).
- Contains: `ARCHITECTURE.md`, `STRUCTURE.md`.

## Naming Conventions

**Files:**

- Python modules: `snake_case.py` (e.g., `task_service.py`, `model_gateway.py`).
- Pydantic models: `PascalCase` (e.g., `TaskRecord`, `ApprovalRequest`).
- Enums: `PascalCase` (e.g., `TaskState`, `ToolCategory`, `ApprovalDecision`).
- Tests: `test_*.py` (e.g., `test_contracts.py`, `test_approval_gating.py`).
- Migrations: `NNNN_name.sql` (e.g., `0001_init.sql`, `0002_self_improvement.sql`).
- Manifests: `*_manifest.yaml` (e.g., `deployment.manifest.yaml`, `tool_pack_manifest.yaml`).
- Docker: `Dockerfile.*` (e.g., `Dockerfile.api`, `Dockerfile.worker`).
- Shell scripts: `snake_case.sh` (e.g., `gcp_bootstrap.sh`, `cf_deploy_ai_gateway_worker.sh`).

**Directories:**

- Core package: `src/agent_mesh/` (importable).
- Submodules: `contracts/`, `services/`, `api/`, `worker/`, `tools/`, `sandbox/`, `gui/` (logical layers).
- Infrastructure: `migrations/`, `docker/`, `scripts/`, `cloudflare/` (deployment automation).
- Artifacts: `schemas/`, `manifests/`, `config/` (generated or configuration).

**Functions & Variables:**

- Public functions: `snake_case` (e.g., `run_mesh()`, `load_tool_pack()`, `can_transition()`).
- Private functions: `_snake_case` (e.g., `_run_stub()`, `_resume_after_approval()`).
- Constants: `UPPER_CASE` (e.g., `WRITE_CATEGORIES`, `TERMINAL_STATES`).
- Classes: `PascalCase` (e.g., `TaskService`, `Worker`, `ToolGateway`).

**Database:**

- Tables: `snake_case` (e.g., `tasks`, `approval_records`, `memory_chunks`).
- Columns: `snake_case` (e.g., `task_id`, `created_at`, `payload_hash`).
- Indexes: `idx_[table]_[columns]` (e.g., `idx_tasks_tenant_state`, `idx_task_events_task`).

## Where to Add New Code

**New Feature (e.g., "add a new read-only tool"):**

1. **Declare the tool** in `manifests/tool_pack_manifest.yaml`:
   ```yaml
   - name: "my_new_tool"
     provider: "external_api"
     category: "read"
     approval_required: false
     credential_secret_name: "MY_API_KEY"
   ```

2. **Create tool integration adapter** in `src/agent_mesh/tools/adapters/` (new directory):
   ```python
   # src/agent_mesh/tools/adapters/my_new_tool.py
   async def execute(params: dict) -> dict:
       # Resolve credential from Secret Manager
       # Call external API
       # Return result
       pass
   ```

3. **Register in Tool Gateway** (`src/agent_mesh/tools/gateway.py`):
   - Update `ToolGateway.execute()` to dispatch to the adapter.

4. **Add tests** in `tests/`:
   ```python
   # tests/test_my_new_tool.py
   def test_my_new_tool_execution():
       # Test with mocked API
       pass
   ```

5. **Update AI-BOM** (`src/agent_mesh/contracts/models.py::AIBOMSnapshot`):
   - Add tool descriptor with version, input/output schema refs.

**New Subagent Role (e.g., "domain expert"):**

1. **Extend Deep Agents roster** in `src/agent_mesh/worker/orchestrator.py`:
   - Define new subagent role (prompt, tools assigned, context isolation).
   - Update supervisor node logic to invoke it.

2. **Add to AI-BOM** (`AIBOMSnapshot.agents`):
   - Capture the new role, prompt version, assigned tools.

3. **Test end-to-end** in `tests/test_orchestrator.py`:
   - Verify supervisor invokes the new role at the right decision point.

**New Approval Policy (e.g., "financial transactions over USD 10k require CFO sign-off"):**

1. **Extend approval routing logic** in `src/agent_mesh/services/approvals.py`:
   ```python
   def route_approval_to(call: ToolCall, decision_required: bool) -> list[str]:
       # Determine approver(s) based on tool category, amount, etc.
       if call.category == ToolCategory.FINANCIAL and call.parameters.get("amount", 0) > 10000:
           return ["cfo_slack_id"]
       # Default routing
       return [call.requester_id]
   ```

2. **Update Slack/MCP approval delivery** in `src/agent_mesh/api/app.py`:
   - Use `route_approval_to()` to target the right requester(s).

3. **Test approval routing** in `tests/test_approval_gating.py`:
   - Verify high-value transactions route to CFO; low-value to requester.

**New Contract Model (e.g., "BudgetAlert"):**

1. **Define in** `src/agent_mesh/contracts/models.py`:
   ```python
   class BudgetAlert(_Base):
       alert_id: str = Field(default_factory=_new_id)
       tenant_id: str
       threshold_usd: float
       triggered_at: datetime = Field(default_factory=_utcnow)
   ```

2. **Export JSON Schema** in `src/agent_mesh/contracts/export_schemas.py`:
   - Add `BudgetAlert` to the export list.

3. **Persist in repository** (`src/agent_mesh/services/repository.py`):
   - Add `create_budget_alert()`, `get_budget_alerts()` methods.

4. **Update migration** `migrations/0001_init.sql`:
   ```sql
   CREATE TABLE IF NOT EXISTS budget_alerts (
       alert_id TEXT PRIMARY KEY,
       tenant_id TEXT NOT NULL,
       threshold_usd FLOAT NOT NULL,
       triggered_at TIMESTAMPTZ NOT NULL
   );
   ```

**New Ingress Channel (e.g., "email-to-task via SendGrid webhooks"):**

1. **Add endpoint** to `src/agent_mesh/api/app.py`:
   ```python
   @app.post("/webhooks/sendgrid")
   async def sendgrid_webhook(request: Request) -> Response:
       body = await request.json()
       req = request_from_email(
           tenant_id=...,
           from_address=body["from"]["email"],
           subject=body["subject"],
           text=body["text"]
       )
       _service.create_task(req)
       return Response(status_code=200)
   ```

2. **Add normalization function** in `src/agent_mesh/services/task_service.py`:
   ```python
   def request_from_email(*, tenant_id, from_address, subject, text):
       return TaskRequest(
           entrypoint=Entrypoint.EMAIL,
           requester=RequesterIdentity(
               requester_id=f"email:{from_address}",
               email=from_address,
           ),
           prompt=f"{subject}\n{text}",
           ...
       )
   ```

3. **Add signature verification** if needed (e.g., SendGrid's EventWebhook).

4. **Test** in `tests/test_ingress.py`:
   - Verify email-to-task conversion; check task is created and queued.

**New Deployment Region (e.g., "us-west1" instead of "australia-southeast1"):**

1. **Copy and edit manifest**:
   ```bash
   cp manifests/deployment.manifest.yaml manifests/deployment.us-west1.yaml
   # Edit region: "us-west1"
   ```

2. **Update Cloud SQL terraform or `gcp_bootstrap.sh`**:
   - Change `--region australia-southeast1` to `--region us-west1`.

3. **Deploy** (idempotent scripts detect existing resources):
   ```bash
   ./scripts/gcp_bootstrap.sh --manifest manifests/deployment.us-west1.yaml
   ```

## Special Directories

**`migrations/`:**
- Purpose: Database schema (Cloud SQL Postgres + pgvector).
- Generated: NO (hand-written SQL; applied manually or via migration runner).
- Committed: YES (idempotent DDL; safe to re-apply).
- Governance: One file per schema version; IF NOT EXISTS clauses; tenant partitioning on every table.

**`schemas/contracts/`:**
- Purpose: Exported JSON Schema from Pydantic models.
- Generated: YES (by `make schemas` → `export_schemas.py`).
- Committed: YES (checked in for API documentation and external validator tooling).
- Governance: Regenerate after any change to contract models; verify backward compatibility.

**`schemas/` (tool I/O):**
- Purpose: Tool input/output schemas (e.g., HubSpot create deal parameters).
- Generated: NO (manually written by tool integrators).
- Committed: YES (referenced by tool pack manifest).
- Governance: Update when tool API changes; version in tool pack manifest.

**`.planning/codebase/`:**
- Purpose: GSD codebase analysis output (ARCHITECTURE.md, STRUCTURE.md).
- Generated: YES (by `/gsd:map-codebase`).
- Committed: YES (to keep in-repo documentation fresh for future phases).
- Governance: Regenerated after major refactors; used by `/gsd:plan-phase` and `/gsd:execute-phase` to guide code placement and conventions.

**`docker/`:**
- Purpose: Container images for cloud deployment.
- Generated: NO (hand-written Dockerfiles; built at deploy time).
- Committed: YES (versioned; buildable from source).
- Governance: Multi-stage builds; minimal base images; scan for vulnerabilities before push to Artifact Registry.

**`scripts/`:**
- Purpose: Idempotent deployment automation.
- Generated: NO (shell scripts, hand-written).
- Committed: YES (versioned; safe to re-run).
- Governance: Always use `--dry-run` first (rsync); detect existing resources before creation; log all actions; support rollback.
